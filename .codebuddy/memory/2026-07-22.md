## 新增：桌面歌词悬浮窗功能
- 在控制条「设置」按钮前加了「桌面歌词」开关按钮（`PlayerBar.vue`）。
- 独立 Electron `BrowserWindow`（`lyricsWindow`，透明/置顶/无任务栏/可拖拽），由 `electron/main.js` 的 `createLyricsWindow()` 在 `app.whenReady` 时创建，初始隐藏。
- 通信链路：主渲染进程 `api.pushLyricsData/pushLyricsStyle` → `ipcRenderer.send('lyrics:data'/'lyrics:style')` → 主进程转发到歌词窗口 `webContents.send('lyrics:update'/'lyrics:style')`；开关状态主进程广播 `lyrics:enabled` 回主窗口。
- preload `lyrics` 组：`setEnabled`(invoke) / `pushData` / `pushStyle` / `onEnabledChanged`(主渲染端) / `onUpdate` / `onStyle`(窗口端)。
- 状态持久化在 `library.js`：`desktopLyricsEnabled`、`desktopLyrics`(fontSize/color/bgColor/bgOpacity/showNext/align)，经 saveSettings/loadSettings 落库；App.vue onMounted 若 enabled 则恢复窗口。
- 样式设置在 `SettingsPanel.vue` 新增「桌面歌词」区块。
- 窗口页面：`public/desklyrics.html`（纯 HTML/JS，无构建依赖），dev 走 `localhost:5173/desklyrics.html`，prod 走 `dist/desklyrics.html`。

## 补充：位置持久化 + 两个开关
- 窗口位置持久化：`electron/main.js` 新增 `saveLyricsBounds()`，在 `moved`/`resize`(防抖300ms)/`hide` 时把 `getBounds()` 合并写入 `settings.json` 的 `lyricsWindowBounds`；`createLyricsWindow()` 启动时读取并 `setBounds` 恢复，同时恢复 `alwaysOnTop`。

- `SettingsPanel.vue`「桌面歌词」区块新增两个开关：「始终置顶显示」「鼠标穿透」。
- 原窗口页内临时锁定按钮已移除（功能由「鼠标穿透」设置替代）。

## 修复：鼠标穿透无效（2026-07-22 后续）
- 原因：原实现仅用渲染层 CSS `pointer-events:none`，这只屏蔽页面 DOM 事件，**无法让 OS 层面窗口变透明**，Windows 上 hWnd 仍挡点击，所以穿透不生效。
- 修复（仅 `electron/main.js`）：改用 `lyricsWindow.setIgnoreMouseEvents(true, { forward: true })` 真正在 OS 层面穿透。新增 `setLyricsClickThrough(enabled)` 辅助函数；在 `lyrics:setEnabled`（开启时按已保存设置应用）与 `lyrics:style`（接收 `clickThrough` 字段）两处调用；并在窗口 `webContents.on('mousemove')` 监听，鼠标移到右上角工具栏区域时临时 `setIgnoreMouseEvents(false)` 以保留关闭按钮可点击（离开后恢复穿透）。这是 Electron 官方推荐的局部可点击模式。
- 渲染层 `desklyrics.html` 的 `pointer-events` 设置保留作冗余保险，不影响穿透。

## 修复：有歌词但未到当前句时样式未应用（2026-07-22 后续）
- 现象：切歌时若歌曲有歌词但还没到第一句，`update()` 走 `showPlaceholder()`，占位元素 `#placeholder` 用固定小字号+半透明白，未套用用户配置字体大小/颜色；而"无歌词"分支渲染到 `#current` 样式正常。
- 修复（`public/desklyrics.html`）：将 `!d.current` 分支改为渲染到 `#current`（带 `paused` 样式、`♪` 前缀），以套用已配置样式。该文件为静态资源，dev 下重新开关桌面歌词即可；打包需重新 `vite build`。
